## C++ da operatorlarni qayta yuklash

!img c_opover.png | + operatoriga yangi narsa o'rgatamiz | 6.2

**Bu mavzuda nimani bilib olasan:**

- operatorlarni qayta yuklash nima ekanini;
- o'z klassing uchun `+`, `==`, `<<` kabi operatorlarni yaratishni;
- qaysi operatorlarni qayta yuklash mumkin va qaysilarini mumkin emasligini.

### Umumiy ma'lumot

`3 + 4` ni C++ biladi. `string("Sa") + "lom"` ni ham biladi. Lekin sen o'zing yaratgan `Vektor` klassining ikki obyektini `v1 + v2` deb qo'shmoqchi bo'lsang-chi? C++ buni qanday qilishni bilmaydi — unga **o'rgatish** kerak.

**Operatorlarni qayta yuklash** (operator overloading) — bu mavjud operatorlarga (`+`, `-`, `==`, `<<` va boshqalar) o'z klassing bilan ishlashni o'rgatish. Natijada kod tabiiy va chiroyli ko'rinadi: `v1.qosh(v2)` o'rniga `v1 + v2`.

!img m11_opover.png | Ikki vektorni + bilan qo'shish | 5.8

### Birinchi misol: vektorlarni qo'shish

Operator `operator` kalit so'zi va operator belgisi bilan yoziladigan maxsus funksiya sifatida aniqlanadi:

```cpp
#include <iostream>
using namespace std;

class Vektor {
public:
    int x, y;
    Vektor(int x = 0, int y = 0) : x(x), y(y) {}

    Vektor operator+(const Vektor& b) const {      // + ni o'rgatamiz
        return Vektor(x + b.x, y + b.y);
    }
    Vektor operator*(int k) const {                // songa ko'paytirish
        return Vektor(x * k, y * k);
    }
    bool operator==(const Vektor& b) const {       // tenglik
        return x == b.x && y == b.y;
    }
};

int main() {
    Vektor a(1, 2), b(3, 4);
    Vektor c = a + b;              // aslida: a.operator+(b)
    Vektor d = a * 3;
    cout << "a + b = (" << c.x << ", " << c.y << ")" << endl;
    cout << "a * 3 = (" << d.x << ", " << d.y << ")" << endl;
    cout << "a == b ? " << (a == b ? "ha" : "yo'q") << endl;
    return 0;
}
```

```output
a + b = (4, 6)
a * 3 = (3, 6)
a == b ? yo'q
```

### `<<` operatorini qayta yuklash — chiroyli chiqarish

`cout << vektor;` deb yozish uchun `<<` operatorini qayta yuklaymiz. U klassdan tashqarida yoziladi, chunki chap tomonda `cout` (ya'ni `ostream`) turadi:

```cpp
#include <iostream>
using namespace std;

class Kasr {
public:
    int surat, maxraj;
    Kasr(int s, int m) : surat(s), maxraj(m) {}
    Kasr operator+(const Kasr& b) const {
        return Kasr(surat * b.maxraj + b.surat * maxraj, maxraj * b.maxraj);
    }
};

ostream& operator<<(ostream& out, const Kasr& k) {
    out << k.surat << "/" << k.maxraj;
    return out;                      // zanjir uchun: cout << a << b
}

int main() {
    Kasr a(1, 2), b(1, 3);
    cout << a << " + " << b << " = " << a + b << endl;
    return 0;
}
```

```output
1/2 + 1/3 = 5/6
```

### `++` operatori va `[]` operatori

```cpp
#include <iostream>
using namespace std;

class Hisoblagich {
    int qiymat = 0;
public:
    Hisoblagich& operator++() { ++qiymat; return *this; }   // prefiks: ++h
    int olish() const { return qiymat; }
};

class Kundalik {
    int baholar[5] = {5, 4, 5, 3, 5};
public:
    int& operator[](int i) { return baholar[i]; }            // k[i]
};

int main() {
    Hisoblagich h;
    ++h; ++h; ++h;
    cout << "Hisob: " << h.olish() << endl;

    Kundalik k;
    k[3] = 4;                         // baho tuzatildi
    cout << "4-baho: " << k[3] << endl;
    return 0;
}
```

```output
Hisob: 3
4-baho: 4
```

### Qaysi operatorlarni qayta yuklash mumkin?

| Mumkin | Mumkin emas |
|---|---|
| `+ - * / %` | `.` (nuqta) |
| `== != < > <= >=` | `::` (ko'lam) |
| `= += -= *=` | `?:` (ternar) |
| `++ --` | `sizeof` |
| `<< >>` | `.*` |
| `[] () ->` | |
| `! && \|\|` | |

!eslatma Operatorlarni qayta yuklashda yangi operator o'ylab topib bo'lmaydi (masalan, `**`), operatorlar ustuvorligi va operandlar sonini ham o'zgartirib bo'lmaydi.

### Ichkarida nima bo'ladi?

Operator — aslida maxsus nomli oddiy funksiya! Kompilyator `a + b` ni ko'rganda uni `a.operator+(b)` chaqiruviga aylantiradi. `cout << k` esa `operator<<(cout, k)` ga aylanadi. Ya'ni operatorlarni qayta yuklash — bu yangi imkoniyat emas, balki funksiyani chiroyliroq chaqirish usuli ("sintaktik shakar").

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| `+` ichida obyektning o'zini o'zgartirish | `a + b` dan keyin `a` o'zgarib qoladi — kutilmagan | Yangi obyekt qaytar, `const` qo'y |
| `<<` ni klass ichida a'zo sifatida yozish | Chap operand `cout` bo'lishi kerak | Klassdan tashqarida yoz |
| `<<` dan `ostream&` qaytarmaslik | `cout << a << b` ishlamaydi | `return out;` |
| Mantiqqa zid operatorlar (`+` ayirsa) | Kodni o'qigan odam adashadi | Operator kutilgan ishni bajarsin |

### Boshqa tillarda

| Til | Operatorlarni qayta yuklash |
|---|---|
| C++ | `Vektor operator+(const Vektor& b)` |
| Python | `def __add__(self, other):` |
| C# | `public static Vektor operator +(Vektor a, Vektor b)` |
| Kotlin | `operator fun plus(b: Vektor)` |
| Java | Yo'q! (faqat `String` uchun `+` maxsus) |

**Python:**

```python
class Vektor:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __add__(self, b):
        return Vektor(self.x + b.x, self.y + b.y)
    def __str__(self):
        return f"({self.x}, {self.y})"

print(Vektor(1, 2) + Vektor(3, 4))   # (4, 6)
```

!mashq `Vaqt` klassini yarat (soat va daqiqa). `+` operatorini qayta yukla: 1:45 + 0:30 = 2:15 bo'lsin (daqiqalar 60 dan oshsa, soatga o'tsin). `<<` operatori vaqtni `02:15` ko'rinishida chiqarsin.

### O'zingni tekshir

1. Operatorlarni qayta yuklash nima?
2. `a + b` ifodasini kompilyator qanday funksiya chaqiruviga aylantiradi?
3. Nega `<<` operatori klassdan tashqarida yoziladi?
4. Qaysi operatorlarni qayta yuklab bo'lmaydi? Ikkitasini ayt.

### Xulosa

- Operatorlarni qayta yuklash mavjud operatorlarga o'z klassing bilan ishlashni o'rgatadi.
- Operator `operator+`, `operator==` kabi maxsus nomli funksiya sifatida yoziladi.
- `<<` operatori klassdan tashqarida yoziladi va `ostream&` qaytaradi.
- `.`, `::`, `?:`, `sizeof` operatorlarini qayta yuklab bo'lmaydi.

## C++ da do'st funksiyalar (friend)

!img c_friend.png | Do'stga uy kaliti berilgandek | 6.2

**Bu mavzuda nimani bilib olasan:**

- do'st funksiya va do'st klass nima ekanini;
- ularni qachon ishlatish o'rinli ekanini;
- `friend` va inkapsulyatsiya o'rtasidagi muvozanatni.

### Umumiy ma'lumot

Uyingning eshigi qulflangan — begonalar kira olmaydi. Lekin eng yaqin do'stingga kalit berishing mumkin. U oila a'zosi emas, lekin uyga kira oladi.

Klassning `private` a'zolari ham "qulflangan". Ularga faqat klassning o'z metodlari kira oladi. Lekin klass biror tashqi funksiyani yoki boshqa klassni **do'st** (`friend`) deb e'lon qilsa, u ham `private` a'zolarga murojaat qila oladi.

### Do'st funksiya

```cpp
#include <iostream>
#include <string>
using namespace std;

class Sandiq {
private:
    string sir = "Xazina daraxt ostida!";
    int oltin = 100;

    friend void ochish(const Sandiq& s);    // do'st deb e'lon qilamiz
};

void ochish(const Sandiq& s) {              // oddiy funksiya, lekin do'st
    cout << "Sir: " << s.sir << endl;
    cout << "Oltin tangalar: " << s.oltin << endl;
}

int main() {
    Sandiq s;
    ochish(s);
    // cout << s.sir;   // XATO: main do'st emas
    return 0;
}
```

```output
Sir: Xazina daraxt ostida!
Oltin tangalar: 100
```

E'tibor ber: do'st funksiya klass **a'zosi emas**. U `s.ochish()` deb emas, oddiy funksiya kabi `ochish(s)` deb chaqiriladi va uning ichida `this` yo'q.

### Eng ko'p uchraydigan foydalanish: `<<` operatori

Oldingi mavzuda `<<` operatori `public` maydonlardan foydalangan edi. Agar maydonlar `private` bo'lsa, `<<` ni do'st qilish kerak:

```cpp
#include <iostream>
using namespace std;

class Nuqta {
    int x, y;                                  // private
public:
    Nuqta(int x, int y) : x(x), y(y) {}
    friend ostream& operator<<(ostream& out, const Nuqta& n);
};

ostream& operator<<(ostream& out, const Nuqta& n) {
    return out << "(" << n.x << ", " << n.y << ")";
}

int main() {
    Nuqta a(3, 5);
    cout << "Nuqta: " << a << endl;
    return 0;
}
```

```output
Nuqta: (3, 5)
```

### Do'st klass

Butun bir klassni ham do'st qilish mumkin. Shunda uning barcha metodlari `private` a'zolarga kira oladi:

```cpp
#include <iostream>
using namespace std;

class Batareya {
    int zaryad = 20;
    friend class Zaryadlovchi;               // Zaryadlovchi — do'st
public:
    void holat() const { cout << "Zaryad: " << zaryad << "%" << endl; }
};

class Zaryadlovchi {
public:
    void zaryadla(Batareya& b) {
        b.zaryad = 100;                      // private ga ruxsat bor
        cout << "To'liq zaryadlandi!" << endl;
    }
};

int main() {
    Batareya b;
    b.holat();
    Zaryadlovchi z;
    z.zaryadla(b);
    b.holat();
    return 0;
}
```

```output
Zaryad: 20%
To'liq zaryadlandi!
Zaryad: 100%
```

### Do'stlik qoidalari

| Qoida | Ma'nosi |
|---|---|
| Do'stlik **beriladi**, olinmaydi | Faqat klassning o'zi kimnidir do'st deb e'lon qila oladi |
| Do'stlik **bir tomonlama** | A klass B ni do'st qilsa, B avtomatik A ni do'st qilmaydi |
| Do'stlik **meros qilinmaydi** | Do'stning bolasi avtomatik do'st bo'lmaydi |
| Do'stlik **o'tmaydi** | Do'stingning do'sti — sening do'sting emas |

!maslahat `friend` dan kam va o'ylab foydalan. U inkapsulyatsiyani "teshadi". Agar ko'p funksiyalar `friend` bo'lib ketsa, klass loyihasini qayta ko'rib chiqish kerak.

### Ichkarida nima bo'ladi?

`friend` — faqat **kompilyator uchun ruxsatnoma**. U dastur ishlashiga hech qanday ta'sir qilmaydi va xotirada hech narsa egallamaydi. `private` va `public` ham shunday — ular faqat kompilyatsiya paytida tekshiriladi. Tayyor dasturda barcha maydonlar bir xil, oddiy xotira kataklari.

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| Do'st funksiyani `s.ochish()` deb chaqirish | U a'zo emas | `ochish(s)` |
| Do'st funksiya ichida `this` | Yo'q | Obyektni parametr sifatida ol |
| Do'stlik ikki tomonlama deb o'ylash | Bir tomonlama | Kerak bo'lsa, ikkala klassda e'lon qil |

### Boshqa tillarda

`friend` — C++ ga xos tushuncha. Boshqa tillarda o'xshash imkoniyatlar:

| Til | O'xshash narsa |
|---|---|
| Java | "Paket darajasidagi" kirish (modifikatorsiz) — bir paketdagi klasslar bir-birini ko'radi |
| C# | `internal` — bir loyiha ichida ko'rinadi |
| Python | Hamma narsa ochiq; `_nom` faqat "tegma" degan kelishuv |

### O'zingni tekshir

1. Do'st funksiya nima?
2. Do'st funksiya klass a'zosimi?
3. A klass B ni do'st qilsa, A ham B ning `private` a'zolarini ko'ra oladimi?
4. `friend` qachon ko'p ishlatiladi?

### Xulosa

- `friend` tashqi funksiya yoki klassga `private` a'zolarga murojaat qilish huquqini beradi.
- Do'st funksiya klass a'zosi emas va unda `this` yo'q.
- Do'stlik bir tomonlama, meros qilinmaydi va o'tmaydi.
- Eng ko'p `<<` operatorini qayta yuklashda ishlatiladi.

## C++ da dinamik xotira ajratish

!img c_dynmem.png | Kerak bo'lganda puflab kattalashtir! | 6.2

**Bu mavzuda nimani bilib olasan:**

- statik va dinamik xotira farqini;
- `new` va `delete` operatorlarini;
- dinamik massivlar yaratishni;
- xotira oqishi va "osilib qolgan" ko'rsatkichlardan saqlanishni.

### Umumiy ma'lumot

Tug'ilgan kuningga nechta mehmon kelishini oldindan bilmasang, nechta stul qo'yasan? Agar 50 ta qo'ysang — joy bekorga band bo'ladi. 5 ta qo'ysang — yetmasligi mumkin. Eng yaxshisi — mehmonlar kelganda kerakli miqdorda stul olib kelish.

Dasturlashda ham shunday. Hozirgacha o'zgaruvchilar va massivlar o'lchami **kompilyatsiya paytida** ma'lum bo'lishi kerak edi (`int a[100];`). Lekin ko'pincha kerakli hajm faqat **dastur ishlayotganda** ma'lum bo'ladi: foydalanuvchi nechta o'quvchi kiritadi, faylda nechta qator bor va hokazo.

**Dinamik xotira ajratish** — dastur ishlayotgan paytda kerakli hajmda xotira olish va keyin uni qaytarish.

!img m11_heap.png | new bilan olingan xotira uyumda (heap) joylashadi | 6.0

### `new` va `delete`

| Operator | Vazifasi |
|---|---|
| `new tur` | Bitta qiymat uchun xotira oladi va unga ko'rsatkich qaytaradi |
| `delete p` | `new` bilan olingan xotirani qaytaradi |
| `new tur[n]` | n ta element uchun massiv oladi |
| `delete[] p` | `new[]` bilan olingan massivni qaytaradi |

```cpp
#include <iostream>
using namespace std;

int main() {
    int* p = new int;        // uyumdan bitta int uchun joy
    *p = 42;
    cout << "Qiymat: " << *p << endl;
    delete p;                // joyni qaytaramiz
    p = nullptr;             // xavfsizlik uchun

    double* d = new double(3.14);   // darhol qiymat bilan
    cout << "Kasr: " << *d << endl;
    delete d;
    return 0;
}
```

```output
Qiymat: 42
Kasr: 3.14
```

### Dinamik massiv

Eng foydali holat — o'lchami dastur ishlayotganda aniqlanadigan massiv:

```cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cout << "Nechta o'quvchi? ";
    cin >> n;

    int* baholar = new int[n];          // aynan n ta joy
    for (int i = 0; i < n; i++) {
        cout << i + 1 << "-o'quvchi bahosi: ";
        cin >> baholar[i];
    }
    int jami = 0;
    for (int i = 0; i < n; i++) jami += baholar[i];
    cout << "O'rtacha: " << (double)jami / n << endl;

    delete[] baholar;                   // massiv uchun delete[]
    return 0;
}
```

```output
Nechta o'quvchi? 3
1-o'quvchi bahosi: 5
2-o'quvchi bahosi: 4
3-o'quvchi bahosi: 5
O'rtacha: 4.66667
```

### Dinamik obyektlar

`new` bilan obyektlar ham yaratiladi. Bunda konstruktor chaqiriladi, `delete` da esa destruktor:

```cpp
#include <iostream>
#include <string>
using namespace std;

class Dushman {
    string nom;
public:
    Dushman(string n) : nom(n) { cout << nom << " paydo bo'ldi!" << endl; }
    ~Dushman() { cout << nom << " yengildi!" << endl; }
    void hujum() { cout << nom << " hujum qilmoqda!" << endl; }
};

int main() {
    Dushman* d = new Dushman("Ajdar");
    d->hujum();               // ko'rsatkich orqali: ->
    delete d;                 // destruktor chaqiriladi
    return 0;
}
```

```output
Ajdar paydo bo'ldi!
Ajdar hujum qilmoqda!
Ajdar yengildi!
```

!eslatma Ko'rsatkich orqali obyekt a'zolariga murojaat qilish uchun **strelka** operatori `->` ishlatiladi. `d->hujum()` — bu `(*d).hujum()` ning qisqa yozilishi.

### Ichkarida nima bo'ladi? Stek va uyum

9-modulda dastur xotirasi hududlarini ko'rgan edik. Endi farqni amalda ko'ramiz:

| | Stek | Uyum (heap) |
|---|---|---|
| Qanday olinadi | Avtomatik (`int x;`) | Qo'lda (`new`) |
| Qanday qaytariladi | Avtomatik (blok tugaganda) | Qo'lda (`delete`) |
| Hajmi | Kichik (bir necha MB) | Katta (gigabaytlar) |
| Tezligi | Juda tez | Sekinroq |
| O'lcham qachon ma'lum | Kompilyatsiyada | Dastur ishlayotganda |

`new int` chaqirilganda maxsus "xotira menejeri" uyumdan bo'sh joy qidiradi, uni "band" deb belgilaydi va manzilini qaytaradi. `delete` esa bu joyni yana "bo'sh" deb belgilaydi.

### Uchta xavfli xato

**1. Xotira oqishi (memory leak)** — `delete` ni unutish:

```cpp
void oqish() {
    int* p = new int[1000];
    // delete[] p; unutildi! Har chaqiruvda 4000 bayt yo'qoladi
}
```

**2. Osilib qolgan ko'rsatkich (dangling pointer)** — o'chirilgan xotiradan foydalanish:

```cpp
int* p = new int(5);
delete p;
// *p = 10;   // XAVFLI! Bu xotira endi bizniki emas
```

**3. Ikki marta o'chirish:**

```cpp
int* p = new int(5);
delete p;
// delete p;  // XAVFLI! Dastur qulashi mumkin
```

!maslahat Bu xatolardan qochishning eng yaxshi yo'li — `new`/`delete` ni qo'lda yozmaslik! Ularning o'rniga 7-modulda o'rgangan aqlli ko'rsatkichlarni (`make_unique`, `make_shared`) va 12-modulda o'rganadigan `vector` ni ishlat.

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| `new[]` dan keyin `delete` | Noto'g'ri o'chirish | `delete[]` |
| `new` dan keyin `delete[]` | Noto'g'ri o'chirish | `delete` |
| `delete` dan keyin ko'rsatkichni ishlatish | Osilib qolgan ko'rsatkich | `delete` dan keyin `p = nullptr;` |
| `delete` ni unutish | Xotira oqishi | Aqlli ko'rsatkich ishlat |
| Stekdagi o'zgaruvchini `delete` qilish | Qulash | Faqat `new` bilan olinganini o'chir |

### Boshqa tillarda

| Til | Xotira olish | Xotira qaytarish |
|---|---|---|
| C | `malloc(n)` | `free(p)` |
| C++ | `new` / `new[]` | `delete` / `delete[]` (yoki aqlli ko'rsatkichlar) |
| Java, C# | `new` | Avtomatik (axlat yig'uvchi) |
| Python, JavaScript | Avtomatik | Avtomatik |

**Java** da `new` bor, lekin `delete` yo'q:

```java
int[] baholar = new int[n];   // o'chirish shart emas
```

### O'zingni tekshir

1. Dinamik xotira nima uchun kerak?
2. `new int[10]` bilan olingan xotira qanday qaytariladi?
3. Xotira oqishi nima?
4. `p->f()` nimaning qisqa yozilishi?
5. Dinamik xotira xotiraning qaysi hududida joylashadi?

### Xulosa

- Dinamik xotira dastur ishlayotgan paytda kerakli hajmda olinadi.
- `new` xotira oladi, `delete` qaytaradi; massivlar uchun `new[]` va `delete[]`.
- Dinamik xotira uyumda (heap) joylashadi.
- Xotira oqishi, osilib qolgan ko'rsatkich va ikki marta o'chirish — eng xavfli xatolar.
- Zamonaviy C++ da aqlli ko'rsatkichlar va `vector` afzal.

## C++ da dinamik a'zolar

!img c_dynmembers.png | Klass ichidagi dinamik xotira — katta mas'uliyat | 6.2

**Bu mavzuda nimani bilib olasan:**

- klass ichida dinamik xotiradan foydalanishni;
- "sayoz" va "chuqur" nusxalash farqini;
- "uchlik qoidasi" (Rule of Three) ni.

### Umumiy ma'lumot

Klass maydonlari orasida dinamik xotiraga ko'rsatkich bo'lsa, u **dinamik a'zo** deyiladi. Masalan, o'yinchining inventari (sumkasi) — unga nechta narsa sig'ishi o'yinchidan o'yinchiga farq qiladi. Bunday klasslar juda kuchli, lekin ularni to'g'ri yozish uchun bir nechta muhim qoidalarni bilish kerak.

### Dinamik a'zoli klass

```cpp
#include <iostream>
#include <string>
using namespace std;

class Sumka {
    string* narsalar;    // dinamik massivga ko'rsatkich
    int sigim;
    int soni;
public:
    Sumka(int s) : sigim(s), soni(0) {
        narsalar = new string[sigim];         // konstruktorda olamiz
        cout << sigim << " o'rinli sumka yaratildi" << endl;
    }
    ~Sumka() {
        delete[] narsalar;                    // destruktorda qaytaramiz
        cout << "Sumka tozalandi" << endl;
    }
    void sol(const string& narsa) {
        if (soni < sigim) narsalar[soni++] = narsa;
        else cout << "Sumka to'la!" << endl;
    }
    void korsat() const {
        cout << "Sumkada: ";
        for (int i = 0; i < soni; i++) cout << narsalar[i] << " ";
        cout << endl;
    }
};

int main() {
    Sumka s(3);
    s.sol("qilich");
    s.sol("qalqon");
    s.sol("olma");
    s.sol("kalit");
    s.korsat();
    return 0;
}
```

```output
3 o'rinli sumka yaratildi
Sumka to'la!
Sumkada: qilich qalqon olma 
Sumka tozalandi
```

Bu yerda RAII tamoyilini ko'ryapmiz: xotira konstruktorda olinadi va destruktorda avtomatik qaytariladi.

### Muammo: sayoz nusxalash

Agar `Sumka b = a;` deb nusxa olsak nima bo'ladi? Kompilyator yaratgan standart nusxalash konstruktori barcha maydonlarni shunchaki nusxalaydi — **ko'rsatkichni ham**! Natijada ikkala obyekt **bitta** massivni ko'rsatadi:

| | `a.narsalar` | `b.narsalar` |
|---|---|---|
| Sayoz nusxa | `0x500` → [qilich, qalqon] | `0x500` → o'sha massiv! |
| Chuqur nusxa | `0x500` → [qilich, qalqon] | `0x700` → [qilich, qalqon] (alohida) |

Sayoz nusxada ikki jiddiy muammo bor:

1. `b` ga narsa solsang, `a` da ham paydo bo'ladi.
2. Ikkala obyekt yo'q bo'lganda, ikkala destruktor ham **bitta** xotirani o'chirmoqchi bo'ladi — ikki marta o'chirish, dastur qulaydi!

### Yechim: chuqur nusxalash

O'z nusxalash konstruktorimiz va nusxalab qiymat berish operatorimizni yozamiz:

```cpp
#include <iostream>
#include <string>
using namespace std;

class Sumka {
    string* narsalar;
    int sigim, soni;
public:
    Sumka(int s) : narsalar(new string[s]), sigim(s), soni(0) {}
    ~Sumka() { delete[] narsalar; }

    // 1. Nusxalash konstruktori — chuqur nusxa
    Sumka(const Sumka& b) : narsalar(new string[b.sigim]), sigim(b.sigim), soni(b.soni) {
        for (int i = 0; i < soni; i++) narsalar[i] = b.narsalar[i];
    }
    // 2. Nusxalab qiymat berish operatori
    Sumka& operator=(const Sumka& b) {
        if (this == &b) return *this;          // o'ziga o'zini berish
        delete[] narsalar;                     // eskisini tozalaymiz
        sigim = b.sigim; soni = b.soni;
        narsalar = new string[sigim];
        for (int i = 0; i < soni; i++) narsalar[i] = b.narsalar[i];
        return *this;
    }
    void sol(const string& n) { if (soni < sigim) narsalar[soni++] = n; }
    void korsat(const string& kim) const {
        cout << kim << ": ";
        for (int i = 0; i < soni; i++) cout << narsalar[i] << " ";
        cout << endl;
    }
};

int main() {
    Sumka a(5);
    a.sol("qilich");
    Sumka b = a;            // chuqur nusxa
    b.sol("sehrli tayoq");  // faqat b ga qo'shiladi
    a.korsat("a");
    b.korsat("b");
    return 0;
}
```

```output
a: qilich 
b: qilich sehrli tayoq 
```

### Uchlik qoidasi (Rule of Three)

> Agar klassga **destruktor**, **nusxalash konstruktori** yoki **nusxalab qiymat berish operatori**dan birortasini o'zing yozishing kerak bo'lsa, ehtimol uchalasini ham yozishing kerak.

Zamonaviy C++ da bunga yana ikkitasi — **ko'chirish konstruktori** va **ko'chirib qiymat berish** qo'shilgan (Rule of Five). Ular 13-moduldagi "rvalue" mavzusida tushuntiriladi.

!maslahat Eng yaxshi yo'l — **Rule of Zero** (nollik qoidasi): klass ichida xom ko'rsatkichlar o'rniga `vector`, `string`, `unique_ptr` kabi tayyor vositalardan foydalan. Ular nusxalash va tozalashni o'zlari to'g'ri bajaradi, sen esa hech narsa yozmaysan!

### Ichkarida nima bo'ladi?

Obyekt ichida faqat **ko'rsatkich** (8 bayt) saqlanadi, massivning o'zi esa uyumda. Shuning uchun `sizeof(Sumka)` sumkaga nechta narsa sig'ishidan qat'i nazar bir xil. Obyekt — "sumka egasi", u uyumdagi haqiqiy sumkaning manzilini biladi.

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| Destruktorda `delete[]` yo'q | Xotira oqishi | Destruktor yoz |
| Nusxalash konstruktori yozilmagan | Sayoz nusxa, ikki marta o'chirish | Uchlik qoidasiga amal qil |
| `operator=` da o'ziga o'zini berishni tekshirmaslik | `a = a;` da ma'lumot yo'qoladi | `if (this == &b) return *this;` |
| `operator=` da eski xotirani o'chirmaslik | Xotira oqishi | Avval `delete[]` |

### Boshqa tillarda

Java va Python da barcha obyektlar havola orqali ishlatiladi va `b = a` doim "sayoz nusxa" — ya'ni ikkala nom bitta obyektni ko'rsatadi! Chuqur nusxa uchun maxsus usullar kerak:

**Python:**

```python
import copy
a = ["qilich"]
b = a                  # sayoz: bitta ro'yxat
c = copy.deepcopy(a)   # chuqur: alohida ro'yxat
```

**Java:** `clone()` metodi yoki nusxalash konstruktori qo'lda yoziladi.

C++ da sayoz va chuqur nusxani tushunsang, boshqa tillardagi "nega ikkinchi ro'yxat ham o'zgarib qoldi?" degan sirlarni darhol yechasan.

### Xulosa

- Dinamik a'zo — klass ichidagi dinamik xotiraga ko'rsatkich.
- Xotira konstruktorda olinadi va destruktorda qaytariladi (RAII).
- Standart nusxalash sayoz: ikki obyekt bitta xotirani baham ko'radi.
- Chuqur nusxa uchun nusxalash konstruktori va `operator=` yoziladi (uchlik qoidasi).
- Eng yaxshisi — tayyor konteynerlardan foydalanish (nollik qoidasi).

## C++ da merosxo'rlik

!img c_inherit.png | Bola klasslar ota klassdan meros oladi | 6.2

**Bu mavzuda nimani bilib olasan:**

- merosxo'rlik nima ekanini va u qanday muammoni hal qilishini;
- ota va bola klass yaratishni;
- `protected` kirish modifikatorini;
- konstruktorlar merosxo'rlikda qanday ishlashini;
- metodlarni qayta aniqlashni (override).

### Umumiy ma'lumot

Sen ota-onangdan ko'p narsani meros olgansan: ko'z rangi, soch rangi, balki kulishing ham. Lekin sening o'zingga xos xususiyatlaring ham bor.

**Merosxo'rlik** (inheritance) — mavjud klass asosida yangi klass yaratish. Yangi klass (**bola** yoki hosila klass) eski klassning (**ota** yoki asosiy klass) barcha maydon va metodlarini meros oladi va o'zining yangi imkoniyatlarini qo'shadi.

Hayotiy misol: barcha hayvonlarning ismi va yoshi bor, hammasi ovqat yeydi va uxlaydi. Lekin faqat mushuk miyovlaydi, faqat it vovullaydi, faqat qush uchadi. Umumiy narsalarni bir marta `Hayvon` klassida yozamiz, qolganlari undan meros oladi.

!img m11_inherit.png | Hayvon — ota klass; Mushuk, It, Qush — bola klasslar | 6.0

### Merosxo'rlik sintaksisi

```cpp
class BolaKlass : public OtaKlass {
    // qo'shimcha maydon va metodlar
};
```

```cpp
#include <iostream>
#include <string>
using namespace std;

class Hayvon {                         // ota klass
public:
    string ism;
    int yosh;
    void ye()   { cout << ism << " ovqat yemoqda." << endl; }
    void uxla() { cout << ism << " uxlamoqda. Zzz..." << endl; }
};

class Mushuk : public Hayvon {         // bola klass
public:
    void miyovla() { cout << ism << ": Miyov!" << endl; }
};

class It : public Hayvon {
public:
    string zot;
    void vovulla() { cout << ism << " (" << zot << "): Vov-vov!" << endl; }
};

int main() {
    Mushuk m;
    m.ism = "Mosh";          // Hayvon dan meros
    m.ye();                  // Hayvon dan meros
    m.miyovla();             // o'ziniki

    It i;
    i.ism = "Bo'ribosar";
    i.zot = "Alabay";
    i.uxla();
    i.vovulla();
    return 0;
}
```

```output
Mosh ovqat yemoqda.
Mosh: Miyov!
Bo'ribosar uxlamoqda. Zzz...
Bo'ribosar (Alabay): Vov-vov!
```

### "IS-A" qoidasi

Merosxo'rlikni qachon ishlatishni bilish uchun oddiy test bor: "**B — bu A ning bir turi**" degan gap mantiqiy bo'lsa, merosxo'rlik o'rinli.

| Gap | Mantiqiymi? | Merosxo'rlik |
|---|---|---|
| Mushuk — hayvonning bir turi | Ha | `Mushuk : Hayvon` |
| Kvadrat — shaklning bir turi | Ha | `Kvadrat : Shakl` |
| Mashina — g'ildirakning bir turi | Yo'q! | Mashinada g'ildirak **bor** (HAS-A) — maydon sifatida |

### `protected` — oila uchun

Ota klassdagi `private` a'zolar bola klassga ham **ko'rinmaydi**! Agar faqat bola klasslar ko'ra olishi kerak bo'lsa, `protected` ishlatiladi:

| Modifikator | Klassning o'zi | Bola klass | Tashqi kod |
|---|---|---|---|
| `public` | Ha | Ha | Ha |
| `protected` | Ha | Ha | Yo'q |
| `private` | Ha | Yo'q | Yo'q |

### Konstruktorlar va merosxo'rlik

Bola klass obyekti yaratilganda **avval ota** konstruktori, **keyin bola** konstruktori chaqiriladi. Destruktorlar esa teskari tartibda. Ota konstruktoriga parametr berish uchun initsializatsiya ro'yxatidan foydalaniladi:

```cpp
#include <iostream>
#include <string>
using namespace std;

class Qahramon {
protected:
    string ism;
    int hayot;
public:
    Qahramon(string i, int h) : ism(i), hayot(h) {
        cout << "Qahramon " << ism << " yaratildi" << endl;
    }
    ~Qahramon() { cout << "Qahramon " << ism << " o'yindan chiqdi" << endl; }
    void holat() const { cout << ism << ": " << hayot << " hayot" << endl; }
};

class Sehrgar : public Qahramon {
    int mana;
public:
    Sehrgar(string i) : Qahramon(i, 80), mana(120) {     // ota konstruktorini chaqiramiz
        cout << "Sehrgar tayyor, mana: " << mana << endl;
    }
    ~Sehrgar() { cout << "Sehrgar sehrini yig'ishtirdi" << endl; }
    void sehrla() {
        mana -= 30;
        cout << ism << " olov shari otdi! Mana qoldi: " << mana << endl;
    }
};

int main() {
    Sehrgar s("Merlin");
    s.holat();
    s.sehrla();
    return 0;
}
```

```output
Qahramon Merlin yaratildi
Sehrgar tayyor, mana: 120
Merlin: 80 hayot
Merlin olov shari otdi! Mana qoldi: 90
Sehrgar sehrini yig'ishtirdi
Qahramon Merlin o'yindan chiqdi
```

Uy qurishga o'xshaydi: avval poydevor (ota), keyin devorlar (bola). Buzishda esa teskari: avval devorlar, keyin poydevor.

### Metodni qayta aniqlash

Bola klass ota klassdagi metodni **o'zicha** qayta yozishi mumkin:

```cpp
#include <iostream>
using namespace std;

class Qush {
public:
    void harakat() { cout << "Qush uchmoqda" << endl; }
};

class Pingvin : public Qush {
public:
    void harakat() { cout << "Pingvin suzmoqda (u ucha olmaydi!)" << endl; }
};

int main() {
    Qush q;
    Pingvin p;
    q.harakat();
    p.harakat();
    p.Qush::harakat();     // ota versiyasini ham chaqirish mumkin
    return 0;
}
```

```output

Pingvin suzmoqda (u ucha olmaydi!)
Qush uchmoqda
```

### Merosxo'rlik turlari

| Tur | Sxema | Misol |
|---|---|---|
| Yagona | A → B | Hayvon → Mushuk |
| Ko'p darajali | A → B → C | Hayvon → Sutemizuvchi → Mushuk |
| Ierarxik | A → B, A → C | Hayvon → Mushuk, Hayvon → It |
| Ko'plik | A, B → C | Uchuvchi, Suzuvchi → O'rdak (alohida mavzu) |

### Ichkarida nima bo'ladi?

Bola klass obyekti xotirada ota klass qismini **o'z ichida** saqlaydi. `Sehrgar` obyekti xotirada shunday: avval `Qahramon` qismi (`ism`, `hayot`), keyin `Sehrgar` ning o'z qismi (`mana`). Xuddi matryoshka kabi — katta qo'g'irchoq ichida kichigi bor. Shuning uchun bola obyektni ota sifatida ishlatish mumkin (keyingi mavzular).

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| `class B : A` (`public` yozilmagan) | Standart `private` merosxo'rlik — ota metodlari tashqaridan ko'rinmaydi | `class B : public A` |
| Bola klassda otaning `private` maydoniga murojaat | Xato | Otada `protected` qil |
| Ota konstruktorini chaqirmaslik (parametrli bo'lsa) | `no matching function` | Initsializatsiya ro'yxatida chaqir |
| "HAS-A" munosabatida merosxo'rlik | Noto'g'ri loyiha | Maydon (kompozitsiya) ishlat |

### Boshqa tillarda

| | C++ | Java | Python | C# |
|---|---|---|---|---|
| Sintaksis | `class B : public A` | `class B extends A` | `class B(A):` | `class B : A` |
| Ota konstruktori | `B() : A(...)` | `super(...)` | `super().__init__(...)` | `: base(...)` |
| Ko'plik merosxo'rlik | Bor | Yo'q (faqat interfeyslar) | Bor | Yo'q (faqat interfeyslar) |

**Python:**

```python
class Hayvon:
    def __init__(self, ism):
        self.ism = ism
    def ye(self):
        print(self.ism, "ovqat yemoqda")

class Mushuk(Hayvon):
    def miyovla(self):
        print(self.ism + ": Miyov!")

m = Mushuk("Mosh")
m.ye()
m.miyovla()
```

**Java:**

```java

```

## C++ da klasslar ierarxiyasida turlarni o'zgartirish

!img c_typeconv.png | dynamic_cast — haqiqatan itmi? | 6.2

**Bu mavzuda nimani bilib olasan:**

- bola obyektni ota sifatida ishlatishni (upcasting);
- ota ko'rsatkichini bola ko'rsatkichiga aylantirishni (downcasting);
- `static_cast` va `dynamic_cast` farqini;
- "kesilish" (slicing) muammosini.

### Umumiy ma'lumot

Har bir mushuk — hayvon. Shuning uchun "hayvonlar ro'yxati"ga mushukni qo'shish mumkin. Lekin har bir hayvon mushuk emas! Ro'yxatdan tasodifiy hayvonni olib, "miyovla!" deb bo'lmaydi — u it bo'lib chiqishi mumkin.

Klasslar ierarxiyasida ham shunday ikki yo'nalish bor:

| Yo'nalish | Nima | Xavfsizmi? |
|---|---|---|
| **Upcasting** (yuqoriga) | Bola → Ota (`Mushuk*` → `Hayvon*`) | Doim xavfsiz, avtomatik |
| **Downcasting** (pastga) | Ota → Bola (`Hayvon*` → `Mushuk*`) | Xavfli, tekshirish kerak |

### Upcasting — avtomatik va xavfsiz

```cpp
#include <iostream>
#include <string>
using namespace std;

class Hayvon {
public:
    string ism;
    Hayvon(string i) : ism(i) {}
    void tanishtir() { cout << "Men hayvonman, ismim " << ism << endl; }
};

class Mushuk : public Hayvon {
public:
    Mushuk(string i) : Hayvon(i) {}
    void miyovla() { cout << ism << ": Miyov!" << endl; }
};

void hayvonniKorsat(Hayvon& h) {      // istalgan hayvonni qabul qiladi
    h.tanishtir();
}

int main() {
    Mushuk m("Mosh");
    Hayvon* h = &m;                   // upcasting: avtomatik
    h->tanishtir();
    // h->miyovla();                  // XATO: Hayvon da miyovla yo'q
    hayvonniKorsat(m);                // havola orqali ham upcasting
    return 0;
}
```

```output
Men hayvonman, ismim Mosh
Men hayvonman, ismim Mosh
```

Ota ko'rsatkichi orqali faqat ota klassdagi a'zolarni ko'rish mumkin — go'yo "hayvon ko'zoynagi" bilan qarayapmiz.

### Downcasting: `static_cast` va `dynamic_cast`

Agar `Hayvon*` aslida mushukni ko'rsatayotganini **aniq bilsang**, `static_cast` ishlatish mumkin. Lekin xato qilsang, natija xavfli!

Xavfsiz yo'l — **`dynamic_cast`**. U dastur ishlayotgan paytda tekshiradi: agar obyekt haqiqatan o'sha turda bo'lsa — to'g'ri ko'rsatkich, aks holda `nullptr` qaytaradi. Uning ishlashi uchun ota klassda kamida bitta `virtual` funksiya bo'lishi kerak (keyingi mavzu):

```cpp
#include <iostream>
#include <string>
using namespace std;

class Hayvon {
public:
    string ism;
    Hayvon(string i) : ism(i) {}
    virtual ~Hayvon() {}               // dynamic_cast uchun kerak
};

class Mushuk : public Hayvon {
public:
    Mushuk(string i) : Hayvon(i) {}
    void miyovla() { cout << ism << ": Miyov!" << endl; }
};

class It : public Hayvon {
public:
    It(string i) : Hayvon(i) {}
    void vovulla() { cout << ism << ": Vov!" << endl; }
};

void tekshir(Hayvon* h) {
    if (Mushuk* m = dynamic_cast<Mushuk*>(h)) {
        m->miyovla();
    } else if (It* i = dynamic_cast<It*>(h)) {
        i->vovulla();
    } else {
        cout << "Noma'lum hayvon" << endl;
    }
}

int main() {
    Mushuk m("Mosh");
    It i("Bo'ribosar");
    tekshir(&m);
    tekshir(&i);
    return 0;
}
```

```output
Mosh: Miyov!
Bo'ribosar: Vov!
```

| | `static_cast` | `dynamic_cast` |
|---|---|---|
| Tekshiruv qachon | Kompilyatsiyada | Dastur ishlayotganda |
| Xato bo'lsa | Aniqlanmagan xatti-harakat (xavfli!) | `nullptr` (ko'rsatkich) yoki istisno (havola) |
| Tezlik | Tez | Biroz sekinroq |
| Talab | Yo'q | Ota klassda `virtual` funksiya |

### Kesilish (slicing) muammosi

Agar bola obyektni ota turidagi **oddiy o'zgaruvchiga** (ko'rsatkich yoki havola emas) nusxalasang, bola qismi "kesilib" tashlanadi:

```cpp
#include <iostream>
#include <string>
using namespace std;

class Hayvon {
public:
    string ism = "Hayvon";
};
class Mushuk : public Hayvon {
public:
    string rang = "kulrang";
};

int main() {
    Mushuk m;
    Hayvon h = m;          // kesilish! rang yo'qoldi
    cout << h.ism << endl;
    // cout << h.rang;     // XATO: h da rang yo'q
    return 0;
}
```

```output
Hayvon
```

!maslahat Polimorfik obyektlar bilan ishlaganda har doim **ko'rsatkich** yoki **havola** ishlat, oddiy nusxa emas.

### Ichkarida nima bo'ladi?

Bola obyekt xotirada ota qismini o'z boshida saqlagani uchun (matryoshka!), upcasting juda oddiy: ota ko'rsatkichi obyektning boshini ko'rsatadi va faqat ota qismini "ko'radi".

`dynamic_cast` qanday biladi? `virtual` funksiyali klasslarning har bir obyektida yashirin ko'rsatkich bor — u obyektning **haqiqiy turi** haqidagi ma'lumotni ko'rsatadi. `dynamic_cast` shu ma'lumotni o'qib, javob beradi. Bu haqda keyingi mavzuda batafsil.

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| Noto'g'ri `static_cast` downcast | Aniqlanmagan xatti-harakat | `dynamic_cast` va natijani tekshir |
| `dynamic_cast` natijasini tekshirmaslik | `nullptr` orqali chaqirish — qulash | `if (p) ...` |
| Ota klassda `virtual` yo'q | `dynamic_cast` kompilyatsiya xatosi | Kamida virtual destruktor qo'sh |
| Obyektni qiymat bo'yicha nusxalash | Kesilish | Ko'rsatkich yoki havola ishlat |

### Boshqa tillarda

| | C++ | Java | Python | C# |
|---|---|---|---|---|
| Tur tekshiruvi | `dynamic_cast<Mushuk*>(h)` | `h instanceof Mushuk` | `isinstance(h, Mushuk)` | `h is Mushuk` |
| Aylantirish | `dynamic_cast` | `(Mushuk) h` | Shart emas | `h as Mushuk` |

**Python:**

### O'zingni tekshir

1. Upcasting va downcasting nima?
2. Qaysi biri doim xavfsiz?
3. `dynamic_cast` muvaffaqiyatsiz bo'lsa nima qaytaradi (ko'rsatkichlar uchun)?
4. Kesilish (slicing) nima?

### Xulosa

- Upcasting (bola → ota) avtomatik va xavfsiz.
- Downcasting (ota → bola) xavfli; `dynamic_cast` uni dastur ishlayotganda tekshiradi.
- `dynamic_cast` muvaffaqiyatsiz bo'lsa `nullptr` qaytaradi.
- Bola obyektni ota turidagi oddiy o'zgaruvchiga nusxalash kesilishga olib keladi.
