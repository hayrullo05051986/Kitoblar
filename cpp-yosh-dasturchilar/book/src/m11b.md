## C++ da polimorfizm

!img c_poly.png | Bitta buyruq — har xil ovozlar | 6.2

**Bu mavzuda nimani bilib olasan:**

- polimorfizm nima ekanini;
- kompilyatsiya va ishlash vaqtidagi polimorfizmni;
- `virtual` funksiyalar va `override` ni;
- virtual destruktor nima uchun muhimligini.

### Umumiy ma'lumot

"Polimorfizm" yunoncha so'z bo'lib, "ko'p shakllilik" degan ma'noni bildiradi. Hayotda misol: o'qituvchi "Hammangiz o'z kasbingiz haqida gapirib bering!" desa — shifokor davolash haqida, oshpaz ovqat haqida, uchuvchi samolyot haqida gapiradi. **Buyruq bitta**, lekin har kim uni **o'zicha** bajaradi.

Dasturlashda polimorfizm — bitta interfeys (masalan, bitta funksiya nomi) orqali turli turdagi obyektlar bilan ishlash, bunda har bir obyekt o'z xatti-harakatini ko'rsatadi.

!img m11_poly.png | Bitta Hayvon* ko'rsatkichi orqali turli ovozlar | 6.0

### Polimorfizm turlari

| Tur | Qachon hal qilinadi | Vositalar | Biz qayerda ko'rdik |
|---|---|---|---|
| Kompilyatsiya vaqtidagi (statik) | Kompilyatsiyada | Funksiyalarni qayta yuklash, operatorlarni qayta yuklash, shablonlar | 6, 10, 11-modullar |
| Ishlash vaqtidagi (dinamik) | Dastur ishlayotganda | `virtual` funksiyalar | Shu mavzu |

### Muammo: `virtual` siz

```cpp
#include <iostream>
using namespace std;

class Hayvon {
public:
    void ovozChiqar() { cout << "..." << endl; }
};
class Mushuk : public Hayvon {
public:
    void ovozChiqar() { cout << "Miyov!" << endl; }
};

int main() {
    Mushuk m;
    Hayvon* h = &m;
    h->ovozChiqar();      // Mushuk, lekin Hayvon versiyasi chaqirildi!
    return 0;
}
```

```output
...
```

Kompilyator `h` ning turiga (`Hayvon*`) qarab qaror qildi, u haqiqatda nimani ko'rsatayotganiga emas.

### Yechim: `virtual` funksiyalar

Ota klassdagi funksiyani `virtual` deb belgilasak, chaqiruv **obyektning haqiqiy turiga** qarab, dastur ishlayotgan paytda hal qilinadi:

```cpp
#include <iostream>
#include <string>
using namespace std;

class Hayvon {
public:
    virtual void ovozChiqar() { cout << "..." << endl; }
    virtual ~Hayvon() {}
};

class Mushuk : public Hayvon {
public:
    void ovozChiqar() override { cout << "Miyov!" << endl; }
};
class It : public Hayvon {
public:
    void ovozChiqar() override { cout << "Vov-vov!" << endl; }
};
class Sigir : public Hayvon {
public:
    void ovozChiqar() override { cout << "Muu!" << endl; }
};

int main() {
    Hayvon* ferma[] = { new Mushuk(), new It(), new Sigir(), new Mushuk() };
    for (Hayvon* h : ferma) {
        h->ovozChiqar();          // har biri o'z ovozini chiqaradi!
    }
    for (Hayvon* h : ferma) delete h;
    return 0;
}
```

```output
Miyov!
Vov-vov!
Muu!
Miyov!
```

Mana polimorfizmning kuchi! Ferma tsiklida hayvon qaysi turda ekanini umuman tekshirmaymiz. Ertaga `Echki` klassini qo'shsak, tsiklni o'zgartirish shart emas — u avtomatik ishlaydi.

### `override` kalit so'zi

`override` (C++11) — kompilyatorga "bu funksiya ota klassdagi virtual funksiyani qayta aniqlaydi" deb aytish. Agar xato qilsang (masalan, nomini noto'g'ri yozsang), kompilyator darhol ogohlantiradi:

```cpp
class Mushuk : public Hayvon {
public:
    void ovozChiqarr() override { }   // XATO: bunday virtual funksiya yo'q
};
```

!maslahat Har doim `override` yoz! U kichik xatolarni darhol topishga yordam beradi.

### Virtual destruktor — juda muhim!

Agar bola obyektni ota ko'rsatkichi orqali `delete` qilsang va ota destruktori `virtual` bo'lmasa, faqat ota destruktori chaqiriladi — bola qismi tozalanmaydi:

```cpp
#include <iostream>
using namespace std;

class Ota {
public:
    virtual ~Ota() { cout << "Ota destruktori" << endl; }
};
class Bola : public Ota {
public:
    ~Bola() override { cout << "Bola destruktori" << endl; }
};

int main() {
    Ota* p = new Bola();
    delete p;            // virtual tufayli ikkalasi ham chaqiriladi
    return 0;
}
```

```output
Bola destruktori
Ota destruktori
```

!diqqat Qoida: agar klassda kamida bitta `virtual` funksiya bo'lsa yoki undan meros olinishi rejalashtirilgan bo'lsa, uning destruktorini `virtual` qil.

### Ichkarida nima bo'ladi? Virtual jadval (vtable)

Kompyuter qaysi funksiyani chaqirishni dastur ishlayotganda qanday biladi? Sirli yechim — **virtual jadval** (vtable):

1. `virtual` funksiyasi bor har bir klass uchun kompilyator jadval yaratadi. Unda shu klassning virtual funksiyalari manzillari yoziladi.
2. Har bir obyekt ichida yashirin ko'rsatkich (**vptr**) bo'ladi — u o'z klassining jadvalini ko'rsatadi.
3. `h->ovozChiqar()` chaqirilganda: obyektning vptr ini o'qi → jadvalni top → jadvaldan `ovozChiqar` manzilini ol → shu manzilga sakra.

| Klass | vtable dagi `ovozChiqar` |
|---|---|
| `Hayvon` | `Hayvon::ovozChiqar` |
| `Mushuk` | `Mushuk::ovozChiqar` |
| `It` | `It::ovozChiqar` |

Bu 7-moduldagi funksiyalarga ko'rsatkichlar g'oyasining o'zi! Virtual funksiyalar — aslida kompilyator avtomatik boshqaradigan funksiyalarga ko'rsatkichlar jadvali. Shuning uchun virtual chaqiruv oddiy chaqiruvdan juda oz sekinroq.

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| Ota funksiyada `virtual` yo'q | Ota versiyasi chaqiriladi | `virtual` qo'sh |
| Obyektni qiymat bo'yicha uzatish | Kesilish — polimorfizm ishlamaydi | Ko'rsatkich yoki havola |
| Virtual destruktor yo'q | Bola qismi tozalanmaydi — xotira oqishi | `virtual ~Ota()` |
| Parametrlari farq qiladigan "override" | Yangi funksiya bo'lib qoladi | `override` yozib, kompilyatorga tekshirt |

### Boshqa tillarda

| Til | Polimorfizm |
|---|---|
| C++ | Faqat `virtual` funksiyalar polimorfik |
| Java | Barcha metodlar avtomatik "virtual" (`final` bo'lmasa) |
| C# | `virtual` va `override` kalit so'zlari (C++ ga o'xshash) |
| Python, JavaScript | Hamma metodlar avtomatik polimorfik |

**Python:**

```python
class Hayvon:
    def ovoz(self): print("...")
class Mushuk(Hayvon):
    def ovoz(self): print("Miyov!")
class It(Hayvon):
    def ovoz(self): print("Vov!")

for h in [Mushuk(), It()]:
    h.ovoz()
```

**Java:**

```java
class Mushuk extends Hayvon {
    @Override
    void ovoz() { System.out.println("Miyov!"); }
}
```

Java dagi `@Override` aynan C++ dagi `override` vazifasini bajaradi!

!mashq `Shakl` ota klassini yarat, unda `virtual double yuza()` va `virtual string nom()` bo'lsin. Undan `Doira`, `Kvadrat` va `Uchburchak` klasslarini hosil qil. `Shakl*` massivida turli shakllarni saqlab, tsiklda har birining nomi va yuzasini chiqar.

### O'zingni tekshir

1. Polimorfizm nima?
2. Polimorfizmning qanday ikki turi bor?
3. `virtual` kalit so'zi nima qiladi?
4. `override` nima uchun foydali?
5. Nima uchun ota klass destruktori `virtual` bo'lishi kerak?

### Xulosa

- Polimorfizm — bitta interfeys orqali turli obyektlar bilan ishlash.
- Statik polimorfizm kompilyatsiyada (qayta yuklash, shablonlar), dinamik polimorfizm dastur ishlayotganda (`virtual`) hal qilinadi.
- `virtual` funksiya obyektning haqiqiy turiga qarab chaqiriladi.
- `override` xatolardan saqlaydi; ota klass destruktori `virtual` bo'lishi kerak.
- Ichkarida virtual jadval (vtable) ishlaydi.

## C++ da abstrakt klasslar

!img c_abstract.png | "Shakl" — aniq shakl emas, qoida | 6.2

**Bu mavzuda nimani bilib olasan:**

- sof virtual funksiya va abstrakt klass nima ekanini;
- abstrakt klassdan obyekt yaratib bo'lmasligini;
- abstrakt klasslarni "interfeys" (shartnoma) sifatida ishlatishni.

### Umumiy ma'lumot

"Menga bitta shakl chizib ber" desa, nima chizasan? Doiramni? Kvadratmi? "Shakl" — bu **abstrakt** tushuncha: u mavjud, lekin o'zicha aniq ko'rinishga ega emas. Biz faqat aniq shakllarni — doira, kvadrat, uchburchakni chiza olamiz.

Lekin "shakl" tushunchasi foydali: u barcha shakllar uchun **umumiy qoida** beradi — "har bir shaklning yuzasi va perimetri bo'ladi".

**Abstrakt klass** — o'zidan obyekt yaratib bo'lmaydigan, faqat boshqa klasslar uchun asos bo'lib xizmat qiladigan klass. U kamida bitta **sof virtual funksiya**ga ega bo'ladi.

### Sof virtual funksiya

Sof virtual funksiya — tanasi yo'q, oxiriga `= 0` yozilgan virtual funksiya. U "har bir bola klass bu funksiyani **albatta** o'zi yozishi shart" degan ma'noni bildiradi:

```cpp
virtual double yuza() = 0;     // sof virtual funksiya
```

```cpp
#include <iostream>
#include <string>
using namespace std;

class Shakl {                                   // abstrakt klass
public:
    virtual double yuza() const = 0;            // sof virtual
    virtual double perimetr() const = 0;        // sof virtual
    virtual string nom() const = 0;
    virtual ~Shakl() {}

    void malumot() const {                      // oddiy metod ham bo'lishi mumkin
        cout << nom() << ": yuza = " << yuza()
             << ", perimetr = " << perimetr() << endl;
    }
};

class Doira : public Shakl {
    double r;
public:
    Doira(double r) : r(r) {}
    double yuza() const override { return 3.14159 * r * r; }
    double perimetr() const override { return 2 * 3.14159 * r; }
    string nom() const override { return "Doira"; }
};

class Tortburchak : public Shakl {
    double a, b;
public:
    Tortburchak(double a, double b) : a(a), b(b) {}
    double yuza() const override { return a * b; }
    double perimetr() const override { return 2 * (a + b); }
    string nom() const override { return "To'rtburchak"; }
};

int main() {
    // Shakl s;                 // XATO: abstrakt klassdan obyekt yaratib bo'lmaydi
    Doira d(2);
    Tortburchak t(3, 4);
    Shakl* shakllar[] = {&d, &t};
    for (Shakl* s : shakllar) s->malumot();
    return 0;
}
```

```output
Doira: yuza = 12.5664, perimetr = 12.5664
To'rtburchak: yuza = 12, perimetr = 14
```

### Abstrakt klass — shartnoma

Abstrakt klassni **shartnoma** deb tushunish mumkin: "Agar sen `Shakl` bo'lmoqchi bo'lsang, `yuza()`, `perimetr()` va `nom()` ni albatta yozishing shart". Agar bola klass birorta sof virtual funksiyani yozmasa, u ham abstrakt bo'lib qoladi va undan ham obyekt yaratib bo'lmaydi.

Bu katta loyihalarda juda foydali: bir dasturchi `Shakl` interfeysini yaratadi, boshqalar esa unga mos turli shakllarni qo'shadi va hamma narsa bir-biriga mos ishlashi kafolatlanadi.

### Interfeys — faqat sof virtual funksiyalardan iborat klass

Agar klassda **faqat** sof virtual funksiyalar bo'lsa, u **interfeys** deb ataladi. Interfeys "nima qilish kerak"ligini aytadi, lekin "qanday"ligini umuman aytmaydi:

```cpp
#include <iostream>
using namespace std;

class Chizuvchi {                          // interfeys
public:
    virtual void chiz() const = 0;
    virtual ~Chizuvchi() {}
};

class Uchburchak : public Chizuvchi {
public:
    void chiz() const override {
        cout << "  *" << endl << " ***" << endl << "*****" << endl;
    }
};

class Kvadrat : public Chizuvchi {
public:
    void chiz() const override {
        for (int i = 0; i < 3; i++) cout << "***" << endl;
    }
};

void chizibBer(const Chizuvchi& c) { c.chiz(); cout << endl; }

int main() {
    chizibBer(Uchburchak());
    chizibBer(Kvadrat());
    return 0;
}
```

```output
  *
 ***
*****

***
***
***

```

### Oddiy, abstrakt va interfeys klasslar

| | Oddiy klass | Abstrakt klass | Interfeys |
|---|---|---|---|
| Obyekt yaratish | Mumkin | Mumkin emas | Mumkin emas |
| Sof virtual funksiyalar | Yo'q | Kamida bitta | Faqat shular |
| Oddiy metodlar va maydonlar | Bor | Bo'lishi mumkin | Odatda yo'q |
| Vazifasi | Aniq obyektlar | Umumiy asos + qisman amalga oshirish | Faqat shartnoma |

### Ichkarida nima bo'ladi?

Abstrakt klassning virtual jadvalida sof virtual funksiyalar uchun **haqiqiy manzil yo'q** — u yerda maxsus "bo'sh joy" turadi. Shuning uchun kompilyator bunday klassdan obyekt yaratishga ruxsat bermaydi: aks holda kimdir yo'q funksiyani chaqirib qo'yishi mumkin edi. Bola klass barcha sof funksiyalarni yozgandagina jadvalning hamma kataklari to'ladi va obyekt yaratish mumkin bo'ladi.

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| Abstrakt klassdan obyekt yaratish | `cannot declare variable to be of abstract type` | Bola klassdan yarat |
| Bola klassda sof funksiyani yozmaslik | Bola ham abstrakt bo'lib qoladi | Barcha sof funksiyalarni `override` qil |
| `= 0` o'rniga `= NULL` | Xato | Faqat `= 0` |
| Interfeysda virtual destruktor yo'q | Xotira oqishi | `virtual ~Interfeys() {}` |

### Boshqa tillarda

| | C++ | Java | Python | C# |
|---|---|---|---|---|
| Abstrakt klass | Sof virtual funksiyali klass | `abstract class` | `ABC` + `@abstractmethod` | `abstract class` |
| Interfeys | Faqat sof virtual funksiyali klass | `interface` | Abstrakt klass | `interface` |

**Java:**

```java
abstract class Shakl {
    abstract double yuza();
}
interface Chizuvchi {
    void chiz();
}
```

**Python:**

```python
from abc import ABC, abstractmethod
class Shakl(ABC):
    @abstractmethod
    def yuza(self): pass
```

Java va C# da `interface` uchun alohida kalit so'z bor. C++ da esa bu oddiy klass, faqat barcha funksiyalari sof virtual. Tushuncha bir xil!

!mashq `Qurilma` interfeysini yarat: `yoq()`, `ochir()`, `holat()` sof virtual funksiyalari bo'lsin. Undan `Lampa`, `Televizor` va `Konditsioner` klasslarini hosil qil. "Aqlli uy" massivida barcha qurilmalarni yoqib, holatini chiqar.

### O'zingni tekshir

1. Sof virtual funksiya qanday yoziladi?
2. Abstrakt klass nima?
3. Abstrakt klassdan obyekt yaratish mumkinmi?
4. Interfeys abstrakt klassdan nimasi bilan farq qiladi?

### Xulosa

- Sof virtual funksiya `= 0` bilan yoziladi va tanasi yo'q.
- Kamida bitta sof virtual funksiyasi bor klass — abstrakt klass; undan obyekt yaratib bo'lmaydi.
- Abstrakt klass bola klasslar uchun shartnoma vazifasini bajaradi.
- Faqat sof virtual funksiyalardan iborat klass — interfeys.

## C++ da ko'plik merosxo'rlik

!img c_multi.png | O'rdak ham uchadi, ham suzadi | 6.2

**Bu mavzuda nimani bilib olasan:**

- ko'plik merosxo'rlik nima ekanini;
- nomlar to'qnashuvini hal qilishni;
- "olmos muammosi" va virtual merosxo'rlikni.

### Umumiy ma'lumot

O'rdak — ajoyib qush: u ham uchadi, ham suzadi, ham yuradi. Agar bizda `Uchuvchi` va `Suzuvchi` klasslari bo'lsa, `Ordak` ikkalasining ham imkoniyatlarini meros olishi kerak.

C++ da bir klass **bir nechta** ota klassdan meros olishi mumkin. Bu **ko'plik merosxo'rlik** (multiple inheritance) deyiladi.

!img m11_multi.png | Ordak ikki ota klassdan meros oladi | 5.5

### Sintaksis va oddiy misol

```cpp
#include <iostream>
#include <string>
using namespace std;

class Uchuvchi {
public:
    void uch() { cout << "Osmonda uchyapman!" << endl; }
};

class Suzuvchi {
public:
    void suz() { cout << "Suvda suzyapman!" << endl; }
};

class Ordak : public Uchuvchi, public Suzuvchi {     // ikki ota
public:
    void gaqilla() { cout << "Ga-ga-ga!" << endl; }
};

int main() {
    Ordak o;
    o.uch();        // Uchuvchi dan
    o.suz();        // Suzuvchi dan
    o.gaqilla();    // o'ziniki
    return 0;
}
```

```output
Osmonda uchyapman!
Suvda suzyapman!
Ga-ga-ga!
```

Konstruktorlar ota klasslar **e'lon qilingan tartibda** chaqiriladi: avval `Uchuvchi`, keyin `Suzuvchi`, keyin `Ordak`.

### Muammo 1: nomlar to'qnashuvi

Agar ikkala ota klassda bir xil nomli funksiya bo'lsa, kompilyator qaysi birini chaqirishni bilmaydi:

```cpp
#include <iostream>
using namespace std;

class Printer { public: void ishga_tush() { cout << "Printer ishga tushdi" << endl; } };
class Skaner  { public: void ishga_tush() { cout << "Skaner ishga tushdi" << endl; } };

class KopFunksiyali : public Printer, public Skaner {
public:
    void ishga_tush() {               // o'zimiz hal qilamiz
        Printer::ishga_tush();
        Skaner::ishga_tush();
    }
};

int main() {
    KopFunksiyali q;
    q.ishga_tush();
    q.Printer::ishga_tush();          // aniq birini ham chaqirish mumkin
    return 0;
}
```

```output
Printer ishga tushdi
Skaner ishga tushdi
Printer ishga tushdi
```

### Muammo 2: olmos muammosi (diamond problem)

Agar ikkala ota ham **bitta umumiy bobo** klassdan meros olgan bo'lsa, nevara klassda bobo qismi **ikki marta** bo'lib qoladi:

| Daraja | Klasslar |
|---|---|
| Bobo | `Hayvon` (ism) |
| Ota-ona | `Uchuvchi : Hayvon`, `Suzuvchi : Hayvon` |
| Nevara | `Ordak : Uchuvchi, Suzuvchi` — ikkita `ism`! |

Sxema olmos (romb) shakliga o'xshagani uchun shunday nomlangan. Yechim — **virtual merosxo'rlik**: ota klasslar boboni `virtual` meros oladi va natijada nevarada bobo qismi faqat bitta bo'ladi:

```cpp
#include <iostream>
#include <string>
using namespace std;

class Hayvon {
public:
    string ism;
    Hayvon() { cout << "Hayvon yaratildi" << endl; }
};

class Uchuvchi : virtual public Hayvon { public: void uch() { cout << ism << " uchmoqda" << endl; } };
class Suzuvchi : virtual public Hayvon { public: void suz() { cout << ism << " suzmoqda" << endl; } };

class Ordak : public Uchuvchi, public Suzuvchi {};

int main() {
    Ordak o;            // "Hayvon yaratildi" faqat bir marta!
    o.ism = "Donald";   // noaniqlik yo'q — ism bitta
    o.uch();
    o.suz();
    return 0;
}
```

```output
Hayvon yaratildi
Donald uchmoqda
Donald suzmoqda
```

### Qachon ishlatish kerak?

Ko'plik merosxo'rlik kuchli, lekin murakkablik qo'shadi. Eng xavfsiz va keng tarqalgan usul: **bitta asosiy ota klass + bir nechta interfeys** (faqat sof virtual funksiyali klasslar):

```cpp
class Oyinchi : public Qahramon, public Chizuvchi, public Saqlanuvchi { };
```

!maslahat Agar "B — bu A" (IS-A) munosabati bo'lmasa, merosxo'rlik o'rniga **kompozitsiya**ni ishlat: kerakli obyektni maydon sifatida saqla. Masalan, mashinada dvigatel **bor** — demak, `Dvigatel dvigatel;` maydoni.

### Ichkarida nima bo'ladi?

Ko'plik merosxo'rlikda bola obyekt xotirada barcha ota qismlarini ketma-ket saqlaydi: avval `Uchuvchi` qismi, keyin `Suzuvchi` qismi, keyin o'z maydonlari. Virtual merosxo'rlikda esa umumiy bobo qismi alohida joyda bo'ladi va ota qismlar unga maxsus yashirin ko'rsatkich orqali murojaat qiladi. Shuning uchun virtual merosxo'rlik biroz ko'proq xotira va vaqt talab qiladi.

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| Bir xil nomli metodni chaqirish | `request for member is ambiguous` | `Ota::metod()` deb aniq ko'rsat |
| Olmos ierarxiyasi virtual merosxo'rliksiz | Bobo qismi ikki marta | `virtual public` |
| Har bir ota oldidan `public` yozmaslik | Ikkinchi ota `private` meros bo'ladi | `public A, public B` |

### Boshqa tillarda

| Til | Klasslarning ko'plik merosxo'rligi | Yechim |
|---|---|---|
| C++ | Bor | Virtual merosxo'rlik |
| Python | Bor | MRO (metodlarni qidirish tartibi) avtomatik hal qiladi |
| Java, C# | Yo'q | Bitta ota klass + istalgancha interfeys |
| Kotlin, Swift | Yo'q | Interfeyslar / protokollar |

**Java:**

```java
class Ordak extends Qush implements Uchuvchi, Suzuvchi { }
```

**Python:**

```python
class Ordak(Uchuvchi, Suzuvchi):
    pass
```

Java va C# yaratuvchilari olmos muammosidan qochish uchun klasslarning ko'plik merosxo'rligini ataylab taqiqlashgan.

### O'zingni tekshir

1. Ko'plik merosxo'rlik nima?
2. Ikki ota klassda bir xil nomli metod bo'lsa, uni qanday chaqirish mumkin?
3. Olmos muammosi nima?
4. Olmos muammosi qanday hal qilinadi?

### Xulosa

- Ko'plik merosxo'rlikda klass bir nechta ota klassdan meros oladi.
- Nomlar to'qnashuvi `Ota::metod()` orqali hal qilinadi.
- Olmos muammosida bobo qismi ikki marta takrorlanadi; uni `virtual` merosxo'rlik hal qiladi.
- Eng xavfsiz usul — bitta asosiy klass va bir nechta interfeys.

## C++ da shablonlar

!img c_templates.png | Shablon — kod bosib chiqaradigan muhr | 6.2

**Bu mavzuda nimani bilib olasan:**

- funksiya va klass shablonlarini;
- bir nechta tur parametrli shablonlarni;
- turdan tashqari (son) parametrlarni;
- shablonni maxsus tur uchun alohida yozishni (ixtisoslashtirish).

### Umumiy ma'lumot

10-modulda generic dasturlash bilan tanishib, funksiya shablonlarini ko'rgan edik. Endi shablonlarni chuqurroq o'rganamiz — ayniqsa **klass shablonlarini**. Aynan ular yordamida `vector<int>`, `vector<string>` kabi har qanday tur bilan ishlaydigan konteynerlar yaratilgan.

Shablonni **muhr**ga o'xshatish mumkin: bir marta muhr yasaysan, keyin unga turli rangdagi siyoh surtib, xohlagancha nusxa bosasan. Muhr — shablon, siyoh rangi — tur, bosilgan rasm — tayyor klass yoki funksiya.

### Klass shabloni

Har qanday narsani saqlaydigan "Quti" klassini yaratamiz:

```cpp
#include <iostream>
#include <string>
using namespace std;

template <typename T>
class Quti {
    T ichidagi;
public:
    Quti(T q) : ichidagi(q) {}
    T och() const { return ichidagi; }
    void almashtir(T yangi) { ichidagi = yangi; }
};

int main() {
    Quti<int> sonliQuti(42);
    Quti<string> sovgaQuti("velosiped");
    Quti<double> narxQuti(19.99);

    cout << sonliQuti.och() << endl;
    cout << sovgaQuti.och() << endl;
    sovgaQuti.almashtir("robot");
    cout << sovgaQuti.och() << endl;
    cout << narxQuti.och() << endl;
    return 0;
}
```

```output
42
velosiped
robot
19.99
```

E'tibor ber: klass shablonidan foydalanganda turni burchakli qavsda **aniq ko'rsatish** kerak: `Quti<int>`. (C++17 dan boshlab kompilyator ba'zan uni o'zi aniqlay oladi.)

### Bir nechta tur parametrlari

```cpp
#include <iostream>
#include <string>
using namespace std;

template <typename K, typename V>
class Juftlik {
public:
    K kalit;
    V qiymat;
    Juftlik(K k, V v) : kalit(k), qiymat(v) {}
    void chiqar() const { cout << kalit << " -> " << qiymat << endl; }
};

int main() {
    Juftlik<string, int> ball("Malika", 98);
    Juftlik<int, char> baho(5, 'A');
    ball.chiqar();
    baho.chiqar();
    return 0;
}
```

```output
Malika -> 98
5 -> A
```

### Turdan tashqari parametrlar

Shablon parametri faqat tur emas, **son** ham bo'lishi mumkin. Masalan, o'lchami kompilyatsiyada ma'lum bo'lgan xavfsiz massiv:

```cpp
#include <iostream>
using namespace std;

template <typename T, int N>
class XavfsizMassiv {
    T elementlar[N] = {};
public:
    T& operator[](int i) {
        if (i < 0 || i >= N) {
            cout << "Xato: " << i << "-indeks chegaradan tashqarida!" << endl;
            return elementlar[0];
        }
        return elementlar[i];
    }
    int olcham() const { return N; }
};

int main() {
    XavfsizMassiv<int, 3> m;
    m[0] = 10; m[1] = 20; m[2] = 30;
    m[5] = 99;                        // xavfsiz: ogohlantirish chiqadi
    cout << "O'lcham: " << m.olcham() << ", m[1] = " << m[1] << endl;
    return 0;
}
```

```output
Xato: 5-indeks chegaradan tashqarida!
O'lcham: 3, m[1] = 20
```

Standart kutubxonadagi `std::array<int, 5>` aynan shunday ishlaydi.

### Shablonni ixtisoslashtirish

Ba'zan bitta tur uchun shablon boshqacha ishlashi kerak. Masalan, `bool` qiymatni "ha/yo'q" ko'rinishida chiqarish:

```cpp
#include <iostream>
using namespace std;

template <typename T>
void chiroyliChiqar(T x) { cout << "Qiymat: " << x << endl; }

template <>
void chiroyliChiqar<bool>(bool x) {          // bool uchun maxsus versiya
    cout << "Qiymat: " << (x ? "ha" : "yo'q") << endl;
}

int main() {
    chiroyliChiqar(42);
    chiroyliChiqar(3.5);
    chiroyliChiqar(true);
    return 0;
}
```

```output
Qiymat: 42
Qiymat: 3.5
Qiymat: ha
```

### Ichkarida nima bo'ladi?

Kompilyator `Quti<int>` ni uchratganda, shablondagi har bir `T` ni `int` ga almashtirib, **yangi klass** yasaydi — go'yo sen `QutiInt` degan klassni qo'lda yozgandek. `Quti<string>` uchun esa yana alohida klass. Shuning uchun:

- shablonlar dasturni sekinlashtirmaydi (hammasi kompilyatsiyada);
- lekin ko'p turdan foydalanilsa, tayyor dastur hajmi biroz oshishi mumkin;
- shablon xatolari faqat u aniq tur bilan ishlatilganda ko'rinadi.

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| `Quti q(5);` (eski kompilyatorda) | Tur ko'rsatilmagan | `Quti<int> q(5);` |
| Shablonni `.h` va `.cpp` ga bo'lish | Linker xatosi | Shablonni to'liq header faylda yoz |
| Turda kerakli amal yo'q (`<`, `<<`) | Uzun xato xabari | Turda shu amallarni aniqla |
| `template <typename T>` ni unutish | `T` noma'lum | Har bir shablon oldidan yoz |

### Boshqa tillarda

| | C++ | Java | C# | TypeScript |
|---|---|---|---|---|
| Klass shabloni | `template <typename T> class Quti` | `class Quti<T>` | `class Quti<T>` | `class Quti<T>` |
| Foydalanish | `Quti<int>` | `Quti<Integer>` | `Quti<int>` | `Quti<number>` |
| Son parametri | Bor (`<T, int N>`) | Yo'q | Yo'q | Yo'q |

**Java:**

```java
class Quti<T> {
    private T ichidagi;
    Quti(T q) { ichidagi = q; }
    T och() { return ichidagi; }
}
Quti<String> q = new Quti<>("velosiped");
```

Java da ichkarida faqat bitta klass bo'ladi va turlar dastur ishlayotganda "o'chiriladi". C++ da esa har bir tur uchun alohida, maksimal tez klass yaratiladi.

!mashq `Stek<T>` klass shablonini yarat (ichida massiv bilan): `qosh(T x)`, `ol()` (oxirgisini olib tashlab qaytaradi), `bosh()` (bo'shmi?) metodlari bo'lsin. Uni `int` va `string` bilan sinab ko'r.

## C++ da istisnolarni qayta ishlash

!img c_exceptions.png | catch — xavfsizlik to'ri | 6.2

**Bu mavzuda nimani bilib olasan:**

- istisno (exception) nima ekanini;
- `try`, `throw`, `catch` bilan ishlashni;
- standart istisno klasslarini;
- o'z istisno klassingni yaratishni.

### Umumiy ma'lumot

Sirkdagi dor ustida yuruvchi akrobatni tasavvur qil. Uning ostida **xavfsizlik to'ri** bor. Agar u yiqilsa — to'r uni ushlab qoladi va tomosha davom etadi.

Dasturlarda ham kutilmagan vaziyatlar bo'ladi: nolga bo'lish, mavjud bo'lmagan faylni ochish, foydalanuvchi son o'rniga harf kiritishi, xotira yetmasligi. Bunday vaziyatlar **istisnolar** (exceptions) deyiladi. Agar ular ushlanmasa, dastur qulaydi. C++ da ularni "xavfsizlik to'ri" bilan ushlash mumkin.

!img m11_exception.png | throw istisnoni otadi, catch uni ushlaydi | 6.0

### Uchta kalit so'z

| Kalit so'z | Vazifasi | O'xshatish |
|---|---|---|
| `try` | Xato yuz berishi mumkin bo'lgan kodni o'raydi | Akrobat dor ustida |
| `throw` | Xato yuz berganda istisnoni "otadi" | Akrobat yiqildi |
| `catch` | Otilgan istisnoni ushlaydi va hal qiladi | Xavfsizlik to'ri |

```cpp
#include <iostream>
using namespace std;

double bolish(double a, double b) {
    if (b == 0) {
        throw "Nolga bo'lish mumkin emas!";     // istisno otamiz
    }
    return a / b;
}

int main() {
    try {
        cout << "10 / 2 = " << bolish(10, 2) << endl;
        cout << "10 / 0 = " << bolish(10, 0) << endl;   // bu yerda istisno
        cout << "Bu qator bajarilmaydi" << endl;
    }
    catch (const char* xabar) {
        cout << "Xato ushlandi: " << xabar << endl;
    }
    cout << "Dastur davom etmoqda!" << endl;
    return 0;
}
```

```output
10 / 2 = 5
10 / 0 = Xato ushlandi: Nolga bo'lish mumkin emas!
Dastur davom etmoqda!
```

`throw` bajarilishi bilan funksiya darhol to'xtaydi va boshqaruv eng yaqin mos `catch` ga sakraydi. `try` ichidagi qolgan kod bajarilmaydi.

### Standart istisno klasslari

C++ da `<stdexcept>` kutubxonasida tayyor istisno klasslari bor. Ularning hammasi `std::exception` dan meros oladi va xato matnini `what()` metodi orqali beradi:

| Klass | Qachon ishlatiladi |
|---|---|
| `std::runtime_error` | Dastur ishlayotganda yuz bergan umumiy xato |
| `std::invalid_argument` | Funksiyaga noto'g'ri argument berilgan |
| `std::out_of_range` | Chegaradan tashqariga chiqish (masalan, `vector::at`) |
| `std::bad_alloc` | `new` xotira ajrata olmadi |
| `std::logic_error` | Dastur mantiqidagi xato |

```cpp
#include <iostream>
#include <stdexcept>
#include <string>
using namespace std;

int yoshniTekshir(int yosh) {
    if (yosh < 0) throw invalid_argument("Yosh manfiy bo'lishi mumkin emas");
    if (yosh > 150) throw out_of_range("Yosh juda katta: " + to_string(yosh));
    return yosh;
}

int main() {
    int sinovlar[] = {12, -5, 200};
    for (int y : sinovlar) {
        try {
            int natija = yoshniTekshir(y);       // xato bo'lsa, shu yerda to'xtaydi
            cout << "Yosh qabul qilindi: " << natija << endl;
        }
        catch (const invalid_argument& e) {
            cout << "Noto'g'ri qiymat: " << e.what() << endl;
        }
        catch (const exception& e) {          // boshqa barcha standart istisnolar
            cout << "Xato: " << e.what() << endl;
        }
    }
    return 0;
}
```

```output
Yosh qabul qilindi: 12
Noto'g'ri qiymat: Yosh manfiy bo'lishi mumkin emas
Xato: Yosh juda katta: 200
```

!eslatma Bir nechta `catch` bloki bo'lsa, ular **yuqoridan pastga** tekshiriladi. Shuning uchun aniqroq istisnolarni (bola klasslarni) yuqoriga, umumiylarini (`exception`) pastga yoz. `catch (...)` esa **istalgan** istisnoni ushlaydi.

### O'z istisno klassingni yaratish

```cpp
#include <iostream>
#include <stdexcept>
#include <string>
using namespace std;

class MablagYetarliEmas : public runtime_error {
public:
    double yetishmaydi;
    MablagYetarliEmas(double y)
        : runtime_error("Hisobda mablag' yetarli emas"), yetishmaydi(y) {}
};

class Hamyon {
    double pul = 5000;
public:
    void tola(double summa) {
        if (summa > pul) throw MablagYetarliEmas(summa - pul);
        pul -= summa;
        cout << summa << " so'm to'landi. Qoldi: " << pul << endl;
    }
};

int main() {
    Hamyon h;
    try {
        h.tola(3000);
        h.tola(4000);
    }
    catch (const MablagYetarliEmas& e) {
        cout << e.what() << ". Yana " << e.yetishmaydi << " so'm kerak." << endl;
    }
    return 0;
}
```

```output
3000 so'm to'landi. Qoldi: 2000
Hisobda mablag' yetarli emas. Yana 2000 so'm kerak.
```

### Ichkarida nima bo'ladi? Stekni "yechish"

`throw` bajarilganda C++ juda muhim ishni qiladi — **stekni yechish** (stack unwinding). Istisno funksiyadan funksiyaga yuqoriga "ko'tarilib", mos `catch` ni qidiradi. Yo'lda chiqib ketilayotgan har bir funksiyaning **barcha mahalliy obyektlari uchun destruktorlar avtomatik chaqiriladi**.

Aynan shuning uchun RAII (10-modul) shunchalik muhim: agar resurslar (xotira, fayllar) obyektlar ichida bo'lsa, xato yuz berganda ham ular avtomatik tozalanadi!

Agar istisno hech qayerda ushlanmasa, dastur `std::terminate` bilan majburan to'xtatiladi.

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| `catch (exception e)` (havolasiz) | Kesilish — bola klass ma'lumoti yo'qoladi | `catch (const exception& e)` |
| Umumiy `catch` ni birinchi yozish | Aniq `catch` lar hech qachon ishlamaydi | Aniqdan umumiyga |
| Har bir kichik narsa uchun istisno | Kod chalkash va sekin | Istisnolar — faqat haqiqiy xatolar uchun |
| Destruktorda `throw` | Dastur to'xtatilishi mumkin | Destruktorlardan istisno otma |

### Boshqa tillarda

| | C++ | Java | Python | JavaScript |
|---|---|---|---|---|
| Urinish | `try { }` | `try { }` | `try:` | `try { }` |
| Ushlash | `catch (const E& e) { }` | `catch (E e) { }` | `except E as e:` | `catch (e) { }` |
| Otish | `throw E("...");` | `throw new E("...");` | `raise E("...")` | `throw new Error("...")` |
| Har doim bajarish | Yo'q (RAII ishlatiladi) | `finally { }` | `finally:` | `finally { }` |

**Python:**

```python
try:
    natija = 10 / 0
except ZeroDivisionError as e:
    print("Xato ushlandi:", e)
finally:
    print("Bu har doim bajariladi")
```

**Java:**

```java
try {
    int x = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Xato: " + e.getMessage());
}
```

`try`/`catch` g'oyasi deyarli barcha zamonaviy tillarda bir xil!

!mashq Foydalanuvchidan yoshini so'raydigan funksiya yoz. Agar u manfiy son kiritsa `invalid_argument`, 120 dan katta son kiritsa `out_of_range` istisnosini ot. `main` da istisnolarni ushlab, foydalanuvchidan qayta kiritishni so'ra (to'g'ri qiymat kiritilguncha).

4. Standart istisnolarning xato matnini qaysi metod beradi?
5. "Stekni yechish" paytida nima sodir bo'ladi?

### Xulosa

- Istisno — dastur ishlayotgandagi kutilmagan xato vaziyati.
- `try` xavfli kodni o'raydi, `throw` istisno otadi, `catch` uni ushlaydi.
- Standart istisnolar `std::exception` dan meros oladi va `what()` orqali xabar beradi.
- Istisno otilganda stek yechiladi va mahalliy obyektlarning destruktorlari chaqiriladi.

## C++ da fayllar bilan ishlash

!img c_files.png | Fayl — dasturning kundalik daftari | 6.2

**Bu mavzuda nimani bilib olasan:**

- fayl oqimlari nima ekanini;
- faylga yozish (`ofstream`) va fayldan o'qishni (`ifstream`);
- fayl ochish rejimlarini;
- satrma-satr va so'zma-so'z o'qishni.

### Umumiy ma'lumot

Hozirgacha dasturlarimiz barcha ma'lumotlarni **operativ xotirada** saqlardi. Dastur yopilishi bilan hammasi yo'qolardi: o'yin rekordlari, kiritilgan baholar, sozlamalar. Ma'lumotni uzoq saqlash uchun uni **faylga** — qattiq diskka yozish kerak.

Fayl bilan ishlash xuddi `cin` va `cout` bilan ishlashga o'xshaydi! Farqi shundaki, ma'lumot ekran va klaviatura o'rniga fayldan keladi yoki faylga ketadi. Buning uchun `<fstream>` kutubxonasi kerak.

!img m11_files.png | ofstream — faylga yozish, ifstream — fayldan o'qish | 6.0

### Fayl oqimlari

| Klass | Vazifasi | O'xshashi |
|---|---|---|
| `ofstream` | Faylga yozish (output file stream) | `cout` |
| `ifstream` | Fayldan o'qish (input file stream) | `cin` |
| `fstream` | Ham o'qish, ham yozish | ikkalasi |

### Faylga yozish

```cpp
#include <iostream>
#include <fstream>
using namespace std;

int main() {
    ofstream fayl("baholar.txt");          // fayl yaratiladi (yoki tozalanadi)
    if (!fayl) {
        cout << "Faylni ochib bo'lmadi!" << endl;
        return 1;
    }
    fayl << "Malika 5" << endl;            // cout kabi yozamiz
    fayl << "Jasur 4" << endl;
    fayl << "Laylo 5" << endl;
    fayl.close();                          // faylni yopamiz
    cout << "Baholar faylga yozildi." << endl;
    return 0;
}
```

```output
Baholar faylga yozildi.
```

Dastur ishlagandan keyin papkada `baholar.txt` fayli paydo bo'ladi. Uni Bloknot bilan ochsang, ichida uchta qatorni ko'rasan.

### Fayldan o'qish

```cpp
#include <iostream>
#include <fstream>
#include <string>
using namespace std;

int main() {
    ofstream yoz("baholar.txt");
    yoz << "Malika 5\nJasur 4\nLaylo 5\n";
    yoz.close();

    ifstream oqi("baholar.txt");
    if (!oqi) {
        cout << "Fayl topilmadi!" << endl;
        return 1;
    }
    string ism;
    int baho, jami = 0, soni = 0;
    while (oqi >> ism >> baho) {           // cin kabi o'qiymiz
        cout << ism << ": " << baho << endl;
        jami += baho;
        soni++;
    }
    oqi.close();
    cout << "O'rtacha baho: " << (double)jami / soni << endl;
    return 0;
}
```

```output
Malika: 5
Jasur: 4
Laylo: 5
O'rtacha baho: 4.66667
```

`while (oqi >> ism >> baho)` — fayl tugaguncha yoki o'qishda xato bo'lguncha davom etadi.

### Satrma-satr o'qish

Probelli matnlarni o'qish uchun `getline` ishlatiladi:

```cpp
#include <iostream>
#include <fstream>
#include <string>
using namespace std;

int main() {
    ofstream yoz("sher.txt");
    yoz << "Bahor keldi, gullar ochildi\n";
    yoz << "Qushlar sayradi bog'larda\n";
    yoz.close();

    ifstream oqi("sher.txt");
    string qator;
    int raqam = 1;
    while (getline(oqi, qator)) {
        cout << raqam++ << ": " << qator << endl;
    }
    return 0;
}                                           // fayl avtomatik yopiladi
```

```output
1: Bahor keldi, gullar ochildi
2: Qushlar sayradi bog'larda
```

!eslatma `close()` ni yozish shart emas: fayl obyekti ko'lamdan chiqqanda destruktor faylni avtomatik yopadi. Bu yana RAII! Lekin faylni tez orada qayta ochish kerak bo'lsa, `close()` ni aniq chaqirish yaxshi.

### Fayl ochish rejimlari

| Rejim | Ma'nosi |
|---|---|
| `ios::out` | Yozish (`ofstream` uchun standart) — eski mazmun o'chiriladi |
| `ios::in` | O'qish (`ifstream` uchun standart) |
| `ios::app` | Fayl oxiriga qo'shish (eski mazmun saqlanadi) |
| `ios::binary` | Ikkilik (binary) rejim — rasmlar, musiqa uchun |
| `ios::trunc` | Ochishda faylni tozalash |

Masalan, o'yin rekordlarini ro'yxat oxiriga qo'shish:

```cpp
#include <iostream>
#include <fstream>
using namespace std;

int main() {
    ofstream("rekordlar.txt");                      // bo'sh fayl yaratamiz
    for (int ochko : {120, 340, 95}) {
        ofstream f("rekordlar.txt", ios::app);      // oxiriga qo'shamiz
        f << ochko << endl;
    }
    ifstream oqi("rekordlar.txt");
    int x, eng = 0;
    while (oqi >> x) if (x > eng) eng = x;
    cout << "Eng yuqori rekord: " << eng << endl;
    return 0;
}
```

```output
Eng yuqori rekord: 340
```

### Ichkarida nima bo'ladi? Bufer

Faylga har bir harf yozilganda diskka murojaat qilish juda sekin bo'lardi (disk xotiradan minglab marta sekin!). Shuning uchun fayl oqimlari **bufer** ishlatadi: ma'lumot avval xotiradagi kichik "chelak"ka yig'iladi va chelak to'lganda (yoki fayl yopilganda, yoki `endl`/`flush` chaqirilganda) bir yo'la diskka yoziladi.

Shuning uchun dastur kutilmaganda qulasa, bufer diskka yozilmay qolishi mumkin. Muhim ma'lumotlardan keyin `flush()` chaqirish yoki faylni o'z vaqtida yopish shuning uchun foydali.

### Ko'p uchraydigan xatolar

| Xato | Muammo | To'g'risi |
|---|---|---|
| Fayl ochilganini tekshirmaslik | Fayl yo'q bo'lsa, jim xato | `if (!fayl) { ... }` |
| `ofstream` bilan eski faylni ochish | Eski mazmun o'chib ketadi | Qo'shish uchun `ios::app` |
| `while (!oqi.eof())` bilan o'qish | Oxirgi qator ikki marta o'qilishi mumkin | `while (oqi >> x)` yoki `while (getline(oqi, s))` |
| Fayl yo'li xato (`C:\papka\fayl.txt`) | `\p` maxsus belgi deb tushuniladi | `"C:\\papka\\fayl.txt"` yoki `"C:/papka/fayl.txt"` |

### Boshqa tillarda

**Python** (`with` — fayl avtomatik yopiladi, C++ dagi RAII kabi):

```python
with open("baholar.txt", "w") as f:
    f.write("Malika 5\n")

with open("baholar.txt") as f:
    for qator in f:
        print(qator.strip())
```

**Java:**

```java
try (BufferedReader r = new BufferedReader(new FileReader("baholar.txt"))) {
    String qator;
    while ((qator = r.readLine()) != null) System.out.println(qator);
}
```

| Amal | C++ | Python | Java |
|---|---|---|---|
| Yozish uchun ochish | `ofstream f("a.txt");` | `open("a.txt", "w")` | `new FileWriter("a.txt")` |
| O'qish uchun ochish | `ifstream f("a.txt");` | `open("a.txt")` | `new FileReader("a.txt")` |
| Qo'shish | `ios::app` | `"a"` rejimi | `new FileWriter("a.txt", true)` |
| Satr o'qish | `getline(f, s)` | `f.readline()` | `r.readLine()` |

!mashq "Shaxsiy kundalik" dasturini yoz: foydalanuvchi kiritgan har bir yozuv `kundalik.txt` fayliga `ios::app` rejimida qo'shilsin. Dastur boshida esa avvalgi barcha yozuvlar ekranga chiqarilsin.

### Xulosa

- Fayllar ma'lumotni dastur yopilgandan keyin ham saqlaydi.
- `ofstream` — yozish, `ifstream` — o'qish, `fstream` — ikkalasi; ular `cout`/`cin` kabi ishlaydi.
- Fayl ochilganini doim tekshir; `ios::app` — oxiriga qo'shish rejimi.
- Fayl obyekti yo'q bo'lganda fayl avtomatik yopiladi (RAII).

## 11-modul uchun mini-loyiha: "Qahramonlar jangi" o'yini

Merosxo'rlik, polimorfizm, abstrakt klasslar, istisnolar va fayllarni birlashtirgan kichik jang o'yini:

```cpp
#include <iostream>
#include <fstream>
#include <memory>
#include <string>
#include <stdexcept>
using namespace std;

class Qahramon {
protected:
    string ism;
    int hayot;
public:
    Qahramon(string i, int h) : ism(i), hayot(h) {}
    virtual ~Qahramon() {}
    virtual int hujum() const = 0;                 // sof virtual
    virtual string turi() const = 0;
    void zarbaOl(int z) {
        if (z < 0) throw invalid_argument("Zarba manfiy bo'lishi mumkin emas");
        hayot = max(0, hayot - z);
    }
    bool tirikmi() const { return hayot > 0; }
    string nomi() const { return ism; }
    int hayotQoldi() const { return hayot; }
};

class Jangchi : public Qahramon {
public:
    Jangchi(string i) : Qahramon(i, 120) {}
    int hujum() const override { return 18; }
    string turi() const override { return "Jangchi"; }
};

class Sehrgar : public Qahramon {
    mutable int navbat = 0;
public:
    Sehrgar(string i) : Qahramon(i, 90) {}
    int hujum() const override { return (++navbat % 3 == 0) ? 40 : 12; }   // har 3-zarba kuchli
    string turi() const override { return "Sehrgar"; }
};

int main() {
    unique_ptr<Qahramon> a = make_unique<Jangchi>("Alpomish");
    unique_ptr<Qahramon> b = make_unique<Sehrgar>("Merlin");
    ofstream jurnal("jang.txt");

    int raund = 1;
    try {
        while (a->tirikmi() && b->tirikmi()) {
            int z1 = a->hujum();  b->zarbaOl(z1);
            int z2 = b->hujum();  if (b->tirikmi()) a->zarbaOl(z2);
            jurnal << raund << "-raund: " << a->nomi() << " " << a->hayotQoldi()
                   << ", " << b->nomi() << " " << b->hayotQoldi() << endl;
            raund++;
        }
    } catch (const exception& e) {
        cout << "O'yinda xato: " << e.what() << endl;
    }
    Qahramon* golib = a->tirikmi() ? a.get() : b.get();
    cout << raund - 1 << " raunddan keyin g'olib: " << golib->nomi()
         << " (" << golib->turi() << "), hayoti: " << golib->hayotQoldi() << endl;
    jurnal << "G'olib: " << golib->nomi() << endl;
    cout << "Jang jurnali jang.txt fayliga yozildi." << endl;
    return 0;
}
```

```output
5 raunddan keyin g'olib: Alpomish (Jangchi), hayoti: 44
Jang jurnali jang.txt fayliga yozildi.
```
